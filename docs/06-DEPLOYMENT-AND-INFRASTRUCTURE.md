# 06 — Deployment & Infrastructure

> Sources: `src/Sentinel.AspNetCore/Dockerfile`, `docker-compose.yml`, `kind-pss-cluster.yaml`, `infra/helm/sentinel/**`, `infra/k8s/**`, `infra/keycloak/**`, `infra/observability/**`, `infra/dast/**`, `infra/fapi-conformance/**`, `infra/staging/**`, `infra/certs/generate-certs.sh`.

## 1. Container Build

`src/Sentinel.AspNetCore/Dockerfile` (syntax `docker/dockerfile:1.7`), two stages:

**Stage 1 — build** (`mcr.microsoft.com/dotnet/sdk:10.0.302-noble`):
1. Installs `ca-certificates`, copies `infra/certs/ca.crt` into `/usr/local/share/ca-certificates/sentinel-ca.crt`, runs `update-ca-certificates` — the CA bundle is *assembled at build time* because the chiseled runtime has no shell.
2. Copies only `Directory.Build.props`, `Directory.Packages.props`, `global.json`, `.editorconfig`, `src/`, `samples/` (layer-cache friendly).
3. `dotnet restore --locked-mode samples/Sentinel.Sample.MinimalApi/...` — lock-file enforced (supply-chain reproducibility).
4. `dotnet publish -c Release --no-restore /p:PublishAot=false /p:UseAppHost=false`.

**Stage 2 — runtime** (`mcr.microsoft.com/dotnet/aspnet:10.0.11-noble-chiseled`):
- `ASPNETCORE_URLS=http://+:8080`, `DOTNET_EnableDiagnostics=0`, `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`.
- Copies the assembled `/etc/ssl/certs/ca-certificates.crt` from the build stage.
- Runs as the pre-configured non-privileged user **`app` (UID 1654)**; no root operations; `EXPOSE 8080`; `ENTRYPOINT ["dotnet", "Sentinel.Sample.MinimalApi.dll"]`.
- A `checkov:skip=CKV_DOCKER_2` annotation documents the deliberate absence of `HEALTHCHECK`: the distroless image has no shell/curl, and liveness/readiness are enforced by orchestrator probes (`/healthz`).

The DAST overlay ships a separate API image (`infra/dast/sentinel-api.Dockerfile`) plus a purpose-built **auth proxy** (`infra/dast/auth-proxy/`, `Sentinel.Dast.AuthProxy.csproj`) that mints/signs DPoP proofs so OWASP ZAP can scan sender-constrained endpoints (`infra/dast/zap/dpop-auth-script.zap`).

## 2. Local Stack (`docker-compose.yml`, project `sentinel-fapi2-stack`)

| Service | Image | Exposure | Hardening |
|---|---|---|---|
| `postgres` | `postgres:17-alpine` | 5432 | db `sentinel_dev`; healthcheck `pg_isready` (5 s interval ×10) |
| `keycloak` | `quay.io/keycloak/keycloak:26.6.4` | **8443 only** | `KC_HTTP_ENABLED=false`, `KC_HTTPS_PROTOCOLS: TLSv1.3`, `KC_FEATURES: dpop,par`, health+metrics enabled, realm auto-import from `infra/keycloak/realms` (`start-dev --import-realm`), TLS cert/key mounted from `infra/certs` |
| `redis` | `redis:7.4-alpine` | 6379 | `--save "" --appendonly no` (pure volatile security cache — no persistence attack surface), healthcheck `redis-cli ping` |
| `sentinel-api` | built from `src/Sentinel.AspNetCore/Dockerfile` | 5260→8080 | `ASPNETCORE_ENVIRONMENT=Production`, `Sentinel__Redis__EnableInMemoryFallback=false`, CA mounted at `/var/run/sentinel/ca/ca.crt`, depends_on postgres/redis **healthy** |

Certificates for local runs are generated by `infra/certs/generate-certs.sh` (invoked by CI before container builds and Testcontainers fixtures). A local Kubernetes option exists via `kind-pss-cluster.yaml` (kind cluster with host port mappings 80/443; PSS = Pod Security Standards admission context for the SRE/distributed gates).

Commands (README "Quick Start"):

```bash
docker-compose up --build -d      # full local stack (Keycloak https://localhost:8443, API http://localhost:5260)
docker-compose down -v            # teardown incl. volumes
cd samples/Sentinel.Sample.MinimalApi && dotnet run    # API without compose
```

## 3. Kubernetes Manifests (`infra/k8s/`)

`sentinel-api-deployment.yaml` (canonical production shape):

- **Images**: `ghcr.io/acme/sentinel-api:v1.0.0` for the API plus `ghcr.io/acme/sentinel-migrations:v1.0.0` as both **initContainer** (schema-up before serve) and a **preStop-adjacent migration container** pattern in the pod spec.
- **TLS in-pod**: `ASPNETCORE_URLS=https://+:8080` with `ASPNETCORE_Kestrel__Certificates__Default__Path/KeyPath` from mounted `tls.crt`/`tls.key` (`/var/run/sentinel/tls/`); pod annotations `prometheus.io/path: /metrics`, `prometheus.io/port: "8080"`.
- **Security context** (pod & container): `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `privileged: false`, `readOnlyRootFilesystem: true`, `capabilities.drop: [ALL]`, seccomp `RuntimeDefault`.
- **Probes**: liveness `GET /healthz` HTTPS:8080 (initial 20 s, period 10 s, timeout 3 s, failureThreshold 3); readiness (initial 5 s, period 5 s, timeout 2 s, failureThreshold 2).
- **Resources**: requests 250m/256Mi, limits 500m/512Mi.
- **Secrets**: `ConnectionStrings__Postgres`, `ConnectionStrings__Redis`, `Sentinel__Keycloak__ClientSecret` via `secretKeyRef` → `sentinel-runtime-secrets`.
- **Observability**: `OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.observability.svc.cluster.local:4317`, `OTEL_SERVICE_NAME=sentinel-api`.

Supporting manifests: `sentinel-api-hpa.yaml`, `sentinel-api-pdb.yaml`, `sentinel-network-policy.yaml` (default-deny + scoped ingress), `keycloak-deployment.yaml`, `postgres-deployment.yaml`, `redis-deployment.yaml`, `otel-config.yaml`; staging variants under `infra/k8s/staging/` (separate ingress for Keycloak + API); SRE load CRDs under `infra/k8s/sre/` (`crd-capacity.yaml`, `crd-soak-48h.yaml`, `crd-spike-20k.yaml` — k6-operator distributed load definitions).

## 5. Keycloak Deployment & FAPI 2.0 Enforcement

Realm `sentinel` (`infra/keycloak/realms/sentinel.json`, imported by compose/Helm):

| Property | Value |
|---|---|
| `sslRequired` | `all` |
| `accessTokenLifespan` | 300 s |
| `ssoSessionIdleTimeout` | 1800 s |
| `ssoSessionMaxLifespan` | 28 800 s (matches `KeycloakOptions.SsoSessionMaxLifespanSeconds` default) |
| Client policy | `fapi2-security-policy` → profile `fapi2-security-profile`, condition `any-client`, **enabled** |
| Client `sentinel-api-client` | standard flow, `pkce.code.challenge.method: S256`, `dpop.bound.access.tokens: true` |
| Client `sentinel-m2m-worker` | service accounts, `tls.client.certificate.bound.access.tokens: true` |
| Browser security headers | CSP, HSTS, X-Content-Type-Options, X-Frame-Options, X-Robots-Tag, X-XSS-Protection configured at realm level |

A dedicated DAST realm (`sentinel-dast.json`) isolates scanner traffic (client `sentinel-dast-scanner` with a realm-local secret used only inside the ephemeral DAST stack). Conformance profile: `infra/keycloak/fapi2-conformance-profile.json`; provisioning scripts `infra/keycloak/scripts/provision-fapi-conformance-clients.sh` and `apply-browser-flow-bindings.sh`; enforcement rationale in `docs/KEYCLOAK_FAPI_ENFORCEMENT.md`; OIDF conformance runbook `docs/OIDF_FAPI_CONFORMANCE_RUNBOOK.md` with a self-hosted conformance proxy stack (`infra/fapi-conformance/` — docker-compose + nginx TLS front + `generate-fapi-certs.sh`).

Sentinel consumes Keycloak through: JWKS/OIDC discovery (JwtBearer `ConfigurationManager`, `RequireHttps=true`), token refresh/exchange/revocation services, Admin REST (`KeycloakAdminTokenProvider` + `KeycloakAdminAuthHandler` + `KeycloakAdminCircuitBreakerHandler`), UMA permission endpoint (`KeycloakUmaPermissionService`), social federation configurator (`SocialFederationConfiguratorHostedService`), and outbound DPoP proofs (`KeycloakDpopProofFactory`).

## 6. Observability Stack (`infra/observability/`)

`docker-compose.observability.yml` wires: **OTel Collector** (`otel-collector-contrib 0.127.0`; OTLP receiver; memory_limiter/batch processors; health_check extension) exporting traces → **Tempo** (`otlp/tempo: tempo:4317`), metrics → **Prometheus** (remote-write/prometheus exporter), logs → **Loki** (`otlphttp/loki: http://loki:3100/otlp`). Prometheus scrapes both `sentinel-collector` and `sentinel-api-direct` jobs at **5 s** intervals (the direct job "proves the native scrape path also works" — `MapPrometheusScrapingEndpoint()` at `/metrics`). Alert rules live in `infra/observability/prometheus/alerts.yml` (CI-gate rules) and `infra/monitoring/sre-alerts.yaml` (production SRE rules) — see [08-OPERATIONS-RUNBOOK.md §2](./08-OPERATIONS-RUNBOOK.md) for the exact rule set. .NET integration reference: `docs/OTEL_DOTNET_INTEGRATION_SNIPPET.md`.

## 7. DAST & Conformance Infrastructure (`infra/dast/`)

- **Stack**: `docker-compose.dast.yml` brings up the API (DAST Dockerfile), Keycloak (DAST realm), Redis, Postgres, the DPoP **auth-proxy**, ZAP, and Nuclei; `scripts/wait-for-stack.sh` gates readiness; `scripts/seed-test-data.sh` provisions fixtures; `scripts/run-fapi-conformance.sh` drives conformance checks; `scripts/evaluate-gates.sh` produces the pass/fail gate verdict consumed by `.github/workflows/dast-release-gate.yml`.
- **OWASP ZAP**: `zap-automation-plan.yaml` (automation framework), scan policies `sentinel-dast.policy` / `sentinel-dast-enhanced.policy`, `alert-filters.json` for triage suppression, and `dpop-auth-script.zap` which signs every scanner request with a valid DPoP proof via the auth-proxy.
- **Nuclei templates** (purpose-written for Sentinel): `sentinel-dpop-bearer-downgrade.yaml` (DPoP-bound token presented as Bearer must 401), `sentinel-dpop-missing-proof.yaml` (DPoP scheme without proof must 401), `sentinel-security-headers.yaml`, `sentinel-sqli.yaml`, `sentinel-xss.yaml`, `sentinel-ssrf.yaml`, `sentinel-mass-assignment.yaml`, `tls-version.yaml`, `redis-unauthenticated.yaml`, `keycloak-version-cve.yaml`; scanner config `nuclei-config.yaml`.
- Program documentation: `docs/DAST_AND_PENTEST_PROGRAM.md`, `docs/PENTEST_PROGRAM.md`, RoE templates `docs/PENTEST_ROE_SENTINEL.md` / `PENTEST_ROE_TEMPLATE.md`, pipeline `pentest-gate.yml`.

## 9. Release Path (CI/CD)

From `.github/workflows/security-pipeline.yml` (details in [07 §2](./07-TESTING-AND-QUALITY-ASSURANCE.md)):

1. PR/main: Gates 1–10 (secrets, SAST, dependency audit, build+contract generation, schema-drift, SBOM, IaC scan, image scan, crypto lifecycle tests) → contract gate → 7-project test matrix → Schemathesis fuzz → Native AOT gate → observability gate → FAPI local pre-flight → acceptance E2E.
2. `release/*` branches additionally run `sign-publish`: docker build/push to `ghcr.io/${{ github.repository }}/sentinel-api:${{ github.sha }}`, `cosign attach sbom` (SPDX from Gate 6), **keyless cosign sign** (Sigstore, OIDC `id-token: write`), then `cosign verify` gated on `--certificate-identity-regexp "https://github.com/${{ github.repository }}/.github/workflows/.*"` and `--certificate-oidc-issuer https://token.actions.githubusercontent.com`.
3. Sibling gates: `chaos-gate.yml`, `contract-validation.yml`, `dast-release-gate.yml`, `fapi-conformance-gate.yml`, `migration-gate.yml`, `pentest-gate.yml`, `sre-distributed-gate.yml`, `sre-load-gate.yml`.
4. NuGet libraries pack with `-p:SignSentinelRelease=true` (private key from `SENTINEL_SNK_BASE64`; PublicSign fallback locally).

## 10. Deployment Verification Checklist (operator)

```bash
# 1. Health & TLS
curl -sk https://<host>:8080/healthz            # {"status":"ok","utc":"…"}
# 2. Security headers present (HSTS, CSP default-src 'none', nosniff, DENY)
curl -skI https://<host>:8080/ | grep -Ei 'strict-transport|content-security|x-frame'
# 3. Metrics endpoint exposes Sentinel meter
curl -sk https://<host>:8080/metrics | grep -E 'auth_dpop_failures|crypto_tls_cert_days_remaining'
# 4. DPoP fail-closed behavior (missing proof on DPoP scheme → 401 + challenge)
curl -sk -o /dev/null -D - https://<host>:8080/v1/profile -H "Authorization: DPoP invalid" \
  | grep -i 'www-authenticate'
# 5. Redis outage drill → expect 503 + Retry-After (never silent pass)   [tests/scripts/validate-fail-closed.sh]
# 6. Repo-provided readiness audits
bash tests/infrastructure-tls-audit.sh
bash tests/infrastructure-openapi-audit.sh
```
